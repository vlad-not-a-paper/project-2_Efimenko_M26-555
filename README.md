# Примитивная база данных

Консольное приложение на Python, которое имитирует работу простой базы данных.
Метаданные таблиц хранятся в файле `db_meta.json`, а данные каждой таблицы —
в отдельном JSON-файле в директории `data/` (например, `data/users.json`).

## Установка

Нужен [uv](https://docs.astral.sh/uv/) версии 0.5 и выше.

```bash
git clone <ссылка на репозиторий>
cd project-2_Efimenko_M26-555
uv sync        # или: make install
```

Установка собранного пакета как отдельной команды:

```bash
uv build                        # или: make build
uv tool install dist/*.whl      # или: make package-install
```

## Запуск

```bash
uv run database    # или: make run
```

После установки пакета через `uv tool install` достаточно команды `database`.

## Управление таблицами

| Команда | Описание |
|---|---|
| `create_table <имя_таблицы> <столбец1:тип> <столбец2:тип> ...` | создать таблицу |
| `list_tables` | показать список всех таблиц |
| `drop_table <имя_таблицы>` | удалить таблицу (с подтверждением) |
| `info <имя_таблицы>` | вывести информацию о таблице |
| `help` | справочная информация |
| `exit` | выход из программы |

Поддерживаемые типы данных: `int`, `str`, `bool`.
Столбец `ID:int` добавляется автоматически первым столбцом.

Пример:

```text
>>>Введите команду: create_table users name:str age:int is_active:bool
Таблица "users" успешно создана со столбцами: ID:int, name:str, age:int, is_active:bool

>>>Введите команду: list_tables
- users

>>>Введите команду: drop_table users
Вы уверены, что хотите выполнить "удаление таблицы"? [y/n]: y
Таблица "users" успешно удалена.
```

## CRUD-операции

| Команда | Описание |
|---|---|
| `insert into <имя_таблицы> values (<значение1>, <значение2>, ...)` | создать запись |
| `select from <имя_таблицы>` | прочитать все записи |
| `select from <имя_таблицы> where <столбец> = <значение>` | прочитать записи по условию |
| `update <имя_таблицы> set <столбец1> = <новое_значение1> where <столбец_условия> = <значение_условия>` | обновить записи |
| `delete from <имя_таблицы> where <столбец> = <значение>` | удалить записи (с подтверждением) |

Правила записи значений:

- строки всегда пишутся в кавычках: `"Sergei"` или `'Sergei'`;
- числа — без кавычек: `28`;
- логические значения — `true` или `false`;
- значение `ID` не передаётся в `insert`, оно генерируется автоматически;
- все поля обязательны, а типы значений проверяются по схеме таблицы.

Пример:

```text
>>>Введите команду: insert into users values ("Sergei", 28, true)
Функция insert выполнилась за 0.000 секунд
Запись с ID=1 успешно добавлена в таблицу "users".

>>>Введите команду: select from users where age = 28
Функция select выполнилась за 0.000 секунд
+----+--------+-----+-----------+
| ID |  name  | age | is_active |
+----+--------+-----+-----------+
| 1  | Sergei |  28 |    True   |
+----+--------+-----+-----------+

>>>Введите команду: update users set age = 29 where name = "Sergei"
Запись с ID=1 в таблице "users" успешно обновлена.

>>>Введите команду: delete from users where ID = 1
Вы уверены, что хотите выполнить "удаление записи"? [y/n]: y
Запись с ID=1 успешно удалена из таблицы "users".
```

## Обработка ошибок, подтверждение действий и кэширование

Повторяющаяся логика вынесена в декораторы (`src/primitive_db/decorators.py`):

- `handle_db_errors` перехватывает ошибки (`KeyError`, `ValueError`,
  `FileNotFoundError` и другие) и выводит понятное сообщение, не завершая программу;
- `confirm_action(action_name)` спрашивает подтверждение `[y/n]` перед опасными
  операциями — `drop_table` и `delete`. Любой ответ, кроме `y`, отменяет операцию;
- `log_time` выводит время выполнения функций `insert` и `select`;
- `create_cacher()` — замыкание, которое кэширует результаты одинаковых запросов
  `select`.

Примеры сообщений об ошибках:

```text
>>>Введите команду: abc
Функции abc нет. Попробуйте снова.

>>>Введите команду: insert into users values (Sergei, 28, true)
Некорректное значение: Sergei. Попробуйте снова.

>>>Введите команду: select from users where agee = 28
Ошибка: Таблица или столбец 'agee' не найден.
```
